Why Blue-Green?

Release without the risky cutover.

Keep the current version available while the next version is deployed and tested. The Kubernetes Service controls which version receives traffic.

⚡

Instant Switch

Change the Service selector from blue to green and move traffic to the new release without rebuilding the application.

🛡️

Fast Rollback

If the new version has a problem, point the Service back to blue. The previous deployment stays ready.

🔍

Safe Validation

Deploy and verify green independently before exposing it to production traffic.

Kubernetes Configuration

Simple selector-based switching

The deployment versions use the same application label but different version labels.

apiVersion: v1
kind: Service
metadata:
   name: blue-green-service
spec:
   selector:
     app: blue-green-app
     version: blue # change to green for release
   ports:
    - port: 80
       targetPort: 80
